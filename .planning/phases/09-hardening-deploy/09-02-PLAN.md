    3. SSE latency test - use the client fixture (ASGI transport, in-process):
       ```python
       import asyncio
       import time
       import redis.asyncio as aioredis

       from app.config import settings

       @requires_db
       @pytest.mark.asyncio
       async def test_sse_latency_under_500ms(client):
           r = aioredis.from_url(settings.REDIS_PUB_URL, decode_responses=True)
           received_event = asyncio.Event()
           latency_holder = []

           async def read_stream():
               async with client.stream("GET", "/api/v1/events") as response:
                   start = time.time()
                   # publish signal after connection established
                   await r.publish("signals", '{"type":"perf_test","value":1}')
                   async for line in response.aiter_lines():
                       if line.startswith("data:"):
                           latency_holder.append(time.time() - start)
                           received_event.set()
                           break

           await asyncio.wait_for(read_stream(), timeout=2.0)
           assert latency_holder, "No SSE message received within timeout"
           elapsed = latency_holder[0]
           assert elapsed < 0.5, f"SSE latency {elapsed:.3f}s, expected < 0.5s"
           await r.aclose()
       ```

       Note: The stream may emit a heartbeat (": heartbeat") before the data message.
       Filter out heartbeat lines by checking `line.startswith("data:")`.

    4. For the SSE test, the httpx.AsyncClient uses ASGI transport (in-process), so the
       Redis publish travels through the real event_generator() coroutine. The 1.0s polling
       timeout in stream.py means worst-case latency is ~1.05s in-process; however, the
       SSE generator checks for messages immediately on each loop iteration before sleeping
       0.05s. For the test to reliably pass < 0.5s: publish the message AFTER opening the
       stream but record the start time at the moment of publish.

    5. Include a comment in the test file explaining the measurement methodology:
       "Latency is measured from Redis publish to first SSE data line received by the
       httpx streaming client. This tests the Redis pub/sub -> event_generator -> SSE
       delivery path end-to-end in-process."
